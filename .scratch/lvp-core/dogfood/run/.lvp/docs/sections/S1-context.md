# S1 — Context

## Answers
- **S1.q1 Bayangkan seseorang memakai aplikasi ini — kejadian menjengkelkan apa yang baru saja menimpa mereka tepat sebelum mereka membuka aplikasinya?** — Tadi sore tepatnya. Dua tim booking slot jam 8 malam untuk Sabtu. Yang satu sudah transfer DP dan kirim buktinya ke WhatsApp saya, yang satu belum. Saya lupa mana yang sudah bayar karena catatan di buku telat saya coret. Pas Sabtu malam dua-duanya datang. Satu tim akhirnya pulang padahal sudah bawa sepatu. Malu, dan rugi dua kali. · _EN: Concrete moment: two teams booked the same Saturday 8 pm slot; the owner lost track of which DP (down payment) had arrived because notebook marks lag behind WhatsApp proof-of-transfer shots, so both teams showed up and one went home angry._
- **S1.q2 Siapa yang mengalami masalah ini? Gambarkan satu jenis orang nyata — apa yang mereka lakukan, bukan jabatan.** — Pemilik lapangan futsal kecil seperti saya — punya 2 lapangan, ada kantin kecil, pegawainya cuma satu yang sekalian jadi kasir. Bukan orang IT, semuanya masih manual. Terus pemainnya: anak muda 20-35 tahun yang main rutin tiap minggu, semua urusan lewat HP. · _EN: Two named groups: (a) small futsal-venue owners like the user — 2 courts, a small canteen, one part-cashier employee, non-technical, all-manual today; (b) regular players aged 20-35 who arrange everything from their phones._
- **S1.q3 Enam bulan setelah aplikasi ini ada, apa yang berubah di minggu Anda sampai Anda bilang membangunnya itu berharga?** — Enam bulan lagi, tiap Sabtu malam saya bisa duduk santai di kantin tanpa buka buku dan tanpa telusuri chat. Jadwal besok kelihatan rapi di layar, DP sudah tercatat otomatis, dan tidak ada lagi dua tim di satu slot. Kalau seminggu penuh tanpa bentrok, itu berhasil. · _EN: Success picture: Saturday nights without the notebook or chat archaeology; tomorrow's schedule visible on screen, DP auto-recorded, zero double-booked slots — a full conflict-free week is the bar._
- **S1.q4 Ini sebaiknya hidup di mana — situs web, aplikasi HP, atau keduanya?** — Pemain harus bisa booking dari HP, jadi tampilan di HP wajib nyaman. Saya kelola dari laptop, jadi halaman admin enaknya di layar besar. Dua-duanya lewat web saja — pemain buka lewat link, nggak perlu install dari Play Store. · _EN: Platform: the web, both shapes — a comfortable mobile web view for players, a desktop-friendly admin view; players open a link, no Play Store install._
- **S1.q5 Hari ini Anda menangani urusan ini bagaimana — kertas, pesan chat, spreadsheet, atau ingatan?** — Sekarang pemain chat WhatsApp: 'Bang, Sabtu jam 8 ada?' Saya catat di buku tulis: nama, tanggal, jam. DP-nya transfer bank manual, saya cek satu-satu di m-banking, kalau sudah masuk saya coret di buku. Seringnya saya lupa coret, atau bukti transfer kecampur di ratusan chat grup komunitas. · _EN: Today's workaround: WhatsApp request → paper notebook entry; manual bank-transfer DP checked one by one in m-banking, then crossed off in the notebook; the crossing-off is forgotten and proofs get buried in group chats — the feature donor for S4._
- **S1.q6 Di bulan-bulan pertama, kira-kira ini untuk sekitar lima orang, lima puluh, atau lima ratus?** — Pemain yang balik-main mungkin 80-150 orang. Per minggu sekitar 20-30 booking, paling ramai Jumat-Malam Sabtu. Dua lapangan, tiap slot 1 jam dari jam 8 pagi sampai 11 malam. · _EN: Rough scale: 80-150 returning players, 20-30 bookings per week, busiest Fri-Sat; 2 courts, 1-hour slots from 08:00 to 23:00 — tens-scale, free-tier-friendly, but the peak-day concentration matters for design._
- **S1.q7 Bahasa apa yang akan dilihat orang di layar aplikasinya sendiri?** — Bahasa Indonesia santai. Pemainnya orang lokal, istilahnya pun Indonesia: 'DP', 'jadwal', 'lapangan'. Sebisa mungkin hindari istilah teknis Inggris di layar. · _EN: UI language: casual Bahasa Indonesia with local terms (DP, jadwal, lapangan); avoid English technical jargon on screens._
- **S1.q8 Apakah persetujuan orang lain ikut berpengaruh di sini — bos, pasangan, komunitas, regulator?** — Nggak ada bos atau regulator. Ister ikut setuju, asal uangnya aman dan nggak ribet. Kalau nanti ada pembayaran online, yang perlu disetujui cuma syarat penyedia pembayarannya. · _EN: No boss or regulator; spouse approves as long as money is safe and it stays simple; only a payment provider's terms would need acceptance later._
- **S1.q9 Apa tugas nyata pertama yang harus bisa diselesaikan seseorang di hari pertama — dari awal sampai akhir?** — Hari pertama yang saya mau: seorang pemain buka link, pilih lapangan, pilih slot Sabtu jam 8 malam, bayar DP 30% online, terus dapat konfirmasi. *(dikoreksi lewat loop-back L-01, 2026-11-07: versi pertama = transfer manual + konfirmasi admin — D-011, S4.q14; "online" tidak dibangun di v1, lihat F-02)* Di sisi saya, jadwal Sabtu itu langsung terkunci dan tercatat siapa yang booking. Dari pemain klik sampai saya lihat tercatat — itu tugas hari pertama. · _EN: Day-one task: player opens the link, picks a court, picks Saturday 8 pm, pays the 30% DP, gets a confirmation (corrected via L-01: v1 payment = manual bank transfer + admin confirmation per D-011/S4.q14 — "online" is not built in v1, see F-02); on the owner's side the slot locks and the booking is recorded — the seed of F-01 and of the M0 walking skeleton._

## Decisions this Section
- **D-001** Platform shape: responsive web app — player books on the phone, admin manages on the desktop — User's own choice in S1.q4: web only, players open a link, no store install · status: user_confirmed
- **D-002** v1 ships as an installable browser app (home-screen icon, no store) instead of a store app — designer_filled: a non-technical user cannot know a website can install like an app with no store account or USD 99/yr fee; recorded proactively and shown for correction · status: designer_filled
- **D-003** Two role views from one web app: player view (mobile) and admin/owner view (desktop) — designer_filled: non-technical users do not think in roles; surfaced from the player-vs-admin split in S1.q4 · status: designer_filled
- **D-004** Concurrency rule: two players grabbing the same slot must not both succeed — first confirmed booking wins — designer_filled: concurrency is never asked by non-technical users; the scale in S1.q6 makes it real · status: designer_filled
